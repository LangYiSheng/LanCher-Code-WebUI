# LanCher Code WebUI

本机浏览器里的 LanCher Code 工作台。后端直接使用固定快照 SDK 的原生文件、搜索、命令、会话、审批、Skills 和 MCP 能力；模型自主调用工具，不使用固定生成脚本。React 页面显示项目、对话、工具轨迹、文件差异、进程、设置和用量。工作台以项目侧栏、聊天正文和任务检查器组织信息，使用轻雾背景与统一圆角，支持浅色、深色与窄屏。工具调用、结果与命令使用 Lucide 语义图标，品牌和欢迎入口的 LC 标识随主题变色，助手消息使用 Sparkles 图标与 LanCher 名称。

## 安装与运行

需要 Windows PowerShell、Python 3.14、uv、Node.js 与 npm。Python 与前端依赖均安装到本目录，不复用原 LanCher Code 开发环境。

```powershell
.\setup.ps1
.\start.ps1 -OpenBrowser
.\stop.ps1
```

默认地址为 `http://127.0.0.1:8765`；可使用 `start.ps1 -Port 8770`。服务只监听本机。启动脚本记录自己的 PID；停止脚本核验进程身份后调用服务关闭接口，等待 Agent 与托管进程完成收尾。强制终止需要显式 `stop.ps1 -Force`。 启动与关闭检查直接连接本机服务，避免系统代理干扰，不修改用户代理设置。

前台诊断可使用：

```powershell
.\.venv\Scripts\python.exe -m webui --port 8765
```

`setup.ps1` 校验 `vendor/snapshot.json` 指定 wheel 的 SHA256，再同步 `requirements.lock.txt` 与前端锁文件。SDK 只安装 `vendor/wheels/current/` 的固定 wheel，不采用 editable 安装，也不从原仓库的未提交代码构建。 当前固定源码为 `f3329bc9bcc8b2ef7afd08cc80d3c9f85bcfd61b`，从已提交的 Git 归档在本项目忽略目录构建；SDK 版本仍为 0.1.0，安装脚本会只重装已校验的 SDK wheel，避免同版本快照没有更新。升级依赖前应先停止本项目服务，避免 Windows 锁定正在使用的扩展模块。

## 项目、任务与会话

添加项目时选择本机真实目录。Agent 的文件与命令工具在该项目目录工作，修改会落到所选工程；访问范围由 SDK 的 `read_only`、`project`、`full` 权限模式及审批决定。权限模式属于应用层检查。运行不依赖 Docker。

新建空白对话先作为草稿保留，浏览器保存草稿身份、输入和控制选项，后端不登记正式历史，也不创建 SDK 会话。首次有效任务被接受时即登记正式对话，包括尚在项目队列中等待的任务；取消或供应商失败不会丢掉已接受的首条任务。

侧栏“搜索聊天”按钮打开独立搜索弹窗，按聊天标题、模型、Web/SDK 身份及项目名称、路径查找正式对话，归档与草稿不出现在结果中；归档仍从设置进入。多个关键词必须全部匹配，结果按置顶、更新时间和身份稳定排序。`Ctrl+N` 在当前项目新建或继续空白草稿，没有选定项目时打开项目选择；`Ctrl+K` 打开快速操作面板。

同一个项目的前台任务按提交顺序执行，不同项目可以并行。当前会话运行时，可以追加 follow_up 或 steer 输入；队列可以编辑、移除、改变类型、暂停和恢复。成功完成后会把未暂停的 follow_up 排回项目队尾，让已经排队的其他会话先运行；steer 保持在本轮。取消或失败会暂停队列，人工暂停空队列后追加的输入也保持暂停。

浏览器刷新或断开连接不会停止任务。页面重新取得状态并按事件游标补回消息。停止本轮与停止整个会话分别处理本轮资源和跨轮次托管进程。`lifetime=session` 的后台命令可以跨轮次继续运行，进程面板可读日志、写输入、转后台或停止。

检查器采用左侧内容预览、右侧目录树，顶部标签可以关闭或通过“+”选择项目文件、对话变更、运行、进程、用量和扩展。新标签页采用紧凑的双列入口；文件预览提供换行与复制。两侧面板平滑展开收起，遵循系统与应用的减少动态效果设置；右侧分隔条支持拖动与键盘调整宽度，窄屏改为覆盖面板并隔离底层聊天焦点。

进程页直接列出活动进程，已结束记录单独收起；详情显示命令、PID、保留范围与退出码，只有适用的状态才提供停止、转后台和输入。选择进程自动读取输出，可开启自动跟随，收起面板后停止刷新。运行页优先显示状态、队列和审批数量；用量页优先显示当前上下文、累计消耗和缓存命中率；扩展页直接显示技能与服务状态。

检查器分别提供“项目文件”和“本对话变更”：项目文件用于浏览当前工程源码；变更按当前对话原生文件工具首次编辑前的文本基线判断，只列新增、修改和删除。恢复原文、新增后又删除都会回到无净变化。Shell 命令和 TUI 旧历史没有这份 Web 基线，不会被误算为当前对话的修改。

会话沿用 `项目目录/.lancher/sessions/<UUID>`，可以由 TUI 与 WebUI 轮流使用。同一会话写入锁阻止两个宿主同时修改历史；在 WebUI 释放会话后，再在 TUI 中恢复。重新加载时读取原生 SDK 历史，不自动重放旧工具。当前固定 SDK 没有原生取消归档接口：网页“恢复”恢复 Web 导航，SDK 的 archived 标记保留；TUI 仍可按 UUID 恢复这份完整历史。宿主不会编造 SDK 历史事件。

## 共用配置与设置

模型目录共用用户的 `~/.lancher/lancher.yaml`。MCP 共用 `~/.lancher/mcp.yaml` 与项目 `.lancher/mcp.yaml`；权限规则共用相应 `permissions.yaml`。Skills 由 SDK 按项目和用户范围加载。

没有模型或有效默认模型时，工作台先显示全屏设置引导。全新使用依次展示欢迎、工作台功能动画、配置选择；已有配置缺模型时直接补配置。桌面导入后先预览供应商数、模型数与默认模型；手动设置依次填写供应商、选择模型、测试连接并开始首个对话，正常引导使用单屏布局。协议必须明确选择 OpenAI 兼容或 Anthropic 兼容，API Key 必填；可以发现模型，也可手动填写 API 模型名称。连接测试只查询供应商模型目录，不发送付费对话，可以跳过。已有坏配置保留原条目与密钥，可编辑的问题进入修复步骤，一次验证并保存；无法解析或无法安全编辑的文件显示位置与重试入口。

新增供应商、模型和 MCP 使用完整表单。内部模型与供应商 ID 自动生成并允许创建时修改；MCP 按传输类型要求启动命令或服务 URL。设置错误显示具体对象和字段，点击错误可定位输入框并展开高级区。可读但字段无效的 MCP 可以直接修复，不可读的配置领域禁止保存；其他领域和模型引导仍能读取。

设置工作区按“个人偏好”“模型与能力”“运行与数据”组织八类配置：外观、输入与显示、模型与供应商、MCP 服务、权限规则、Agent 行为、执行与进程、数据与历史。模型采用目录与详情布局，连接、继承、API 形式和高级参数按需展开；密钥已配置与留空保留状态明确显示。页面显示作用范围与保存状态，配置修订号用于后台冲突校验。保存全局配置会影响 TUI；项目配置只作用于当前项目。修订冲突时重新载入，避免覆盖其他窗口的更新。忙时的模型或配置变更等待安全时机应用。API 不把保存的密钥原文发给页面。

每类设置、每个作用范围都有独立草稿。切换分类或关闭后重新打开设置会保留未保存内容；保存或放弃只处理当前分类。无效 JSON 保留原文，并阻止该分类保存。全局与各项目的 MCP、规则草稿互不混用。设置草稿只保存在当前页面内存，刷新页面不会保留，密钥不写入浏览器存储。未保存的外观即时预览；退出设置恢复已保存外观，再次打开可继续预览该草稿。

MCP 按连接类型显示 stdio 环境变量或 HTTP 请求头，删除条目会真正移除键，保留其他已配置密钥与环境引用。清空启动、工具或关闭超时会恢复 SDK 默认值；未编辑的配置仍保留。执行设置提供完整资源限制和命令配置结构。

归档记录集中在“数据与历史”，普通历史侧栏不显示归档开关。可按项目与关键词筛选，查看原生消息和工具记录；归档阅读页没有输入区、运行控制或检查器。显式恢复后，同一 Web 对话与 SDK UUID 回到历史侧栏，历史和工程文件不因查看或恢复而改变。固定 SDK 的原生归档标记仍保留，见上面的会话边界说明。

“关于”分别显示 WebUI 应用版本与 LanCher Code SDK 版本：前者标识工作台自身，后者标识已安装的核心包；SDK 固定提交用于确认同版本包的源码来源，两者不混为一个版本号。当前 WebUI 为 0.2.0，SDK 为 0.1.0，固定来源为 f3329bc。

模型发现使用当前填写的连接读取列表和能力信息，选中模型后先合并到设置草稿，显式保存才写共享配置。同源已有模型保留稳定 ID、显示名与手动覆盖；认证失败后旧结果不可继续导入，连接、作用范围和修订号变化也需要重新发现。

推理强度属于当前对话，可用发送按钮左侧的“模型名 · 等级”入口或 `/effort` 切换，后续任务和压缩继续沿用。组合弹层按供应商分组展示模型，下方滑条只提供当前连接的可用档位，等级简写为低、中、高等；支持搜索模型、键盘调节和 Escape 返回。选项来自连接绑定的能力声明；未知能力与明确不支持会分别显示。切换到不支持原档位的模型时，SDK 恢复 auto。旧模型配置中的思考开关和预算已由这套会话控制取代。

模型和设置使用主题一致的下拉菜单，支持键盘选择。新增、改名与确认操作使用应用内弹窗，显示具体对象和待执行动作。

输入框输入 `/` 查看当前完整命令目录及补全。命令由 Web 宿主派发到 SDK 控制接口或对应设置页面，不交给模型当作普通文本。

用量分为本次回答、会话、项目与服务。实际请求账本包含队列、用户恢复重试和压缩；未上报字段保持未知，部分上报显示已知小计并注明缺失或未完成；缓存命中率直接使用 SDK 对成对有效输入/缓存样本的计算结果，不完整账本会标注估算与样本数。底部用量按钮支持鼠标悬停、键盘聚焦或点击打开内置统计浮层；圆环单独显示当前上下文占模型容量的比例，累计 token 消耗与当前上下文分开统计。

释放后的历史会话通过只读 SDK 投影估算上下文，不创建 Agent、不取得会话写入锁。即使 TUI 正持有同一 UUID，网页仍可查看保存快照。来源会区分本地估算与提供方校准估算，不能估算的字段保持未知。

## 验证与证据

```powershell
$env:PYTHONDONTWRITEBYTECODE='1'
.\.venv\Scripts\python.exe -m pytest -q -p no:cacheprovider
.\.venv\Scripts\python.exe .\scripts\acceptance.py --url http://127.0.0.1:8765
```

自动化测试使用临时模型配置、临时用户目录和临时项目；模型边界使用注入 Provider 或本机真实 HTTP/SSE 服务。原生工具、会话与进程按真实 SDK 路径运行；测试不会写入真实用户配置或原开发仓库。在线验收只在 `data/acceptance_projects/` 的专用工程调用真实模型，结果另行保存。新版 SDK 下 64 项后端测试均有通过证据（完整 55 项加后续 9 项新增定向回归，并非单次完整执行 64 项），59 项前端测试、TypeScript 检查与 Vite 构建通过。实际浏览器验证了独立设置草稿、仅保存当前分类、归档只读查看与同身份恢复、搜索键盘操作、版本信息、主题预览和窄屏。初版 SDK 的两个真实在线项目共 16 项 HTTP 测试通过；新版验证使用真实本机 HTTP 与离线 fixture，未额外调用外部模型，详细证据和验证边界见 [ACCEPTANCE.md](ACCEPTANCE.md)。

本轮在确认正式服务闲置后完成正常重启，8765 已提供最新前端并加载实验 API 移除与 MCP 超时恢复默认补丁，状态与 bootstrap 均返回 200。验收实例已关闭；正式服务随后已有新任务，没有再次重启或强制刷新用户页面。

## 目录与磁盘备份

- `webui/`：后端、共享配置适配、调度和事件传输。
- `frontend/`：React 页面与构建输出。
- `vendor/wheels/current/`、`vendor/snapshot.json`：固定 SDK 及哈希。
- `data/`：Web 专属状态、日志和验收证据，Git 忽略。
- `data/legacy/data/`：保留在磁盘的旧实验数据备份，产品不提供入口或读取接口。

旧 `D:\Dev\LanCher Agent Lab` 保留为历史磁盘备份；旧实验历史入口和读取链已从本产品移除，旧后端和前端不作为运行入口。原 `D:\Dev\LanCher Code` 保持独立，本项目不写其代码、依赖环境或 Git 状态。
